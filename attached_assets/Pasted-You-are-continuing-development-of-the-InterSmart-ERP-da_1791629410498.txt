==================================================
1. PROJECT SCOPE
==================================================

A project can have multiple scope versions.

This is important because scope may change during the lifecycle.

Fields:

- id UUID primary key
- projectId
- versionNumber
- title nullable
- summary nullable
- scopeDescription nullable
- status
- createdById
- approvedById nullable
- approvedAt nullable
- createdAt
- updatedAt

Relationship:

Project
 ↓
ProjectScope[]

Each ProjectScope belongs to exactly one Project.

==================================================
SCOPE STATUS
==================================================

Create:

DRAFT
SUBMITTED
APPROVED
REJECTED
SUPERSEDED

Expected lifecycle:

DRAFT
 ↓
SUBMITTED
 ↓
APPROVED

If a new scope version becomes approved:

Previous APPROVED version
 ↓
SUPERSEDED

Do not physically delete previous approved scope versions.

Historical scope must remain available.

==================================================
SCOPE VERSIONING
==================================================

Use:

projectId + versionNumber

as a unique constraint.

Example:

Project A
 ├── Scope Version 1
 ├── Scope Version 2
 └── Scope Version 3

Only one version should normally be the current approved scope.

Do not add unnecessary `currentVersion` fields unless they provide a real query/performance benefit.

If a current-version field is used, ensure it cannot create inconsistent references.

==================================================
IMPORTANT ARCHITECTURE RULE
==================================================

Do not mix:

Project Scope
Business Analysis
Budget
Tasks
UI Pages
UX
Development

Each represents a different business concept.

Scope defines WHAT is included.

Business Analysis defines WHY and FOR WHOM the project exists.

Budget defines HOW MUCH work is financially allocated.

Tasks define HOW the work is executed.

==================================================
DATA INTEGRITY
==================================================

Requirements:

- ProjectScope.projectId must reference Project.
- ProjectScopeItem.projectScopeId must reference ProjectScope.
- BusinessAnalysis.projectId must reference Project.
- Competitor.businessAnalysisId must reference BusinessAnalysis.
- createdById / approvedById / updatedById must reference User.
- Do not allow orphan records.

Use appropriate onDelete behavior.

IMPORTANT:

Do not cascade-delete historical approved scope accidentally.

If a project is deleted/soft-deleted, its historical scope should remain recoverable according to the existing deletion strategy.

Follow existing project deletion conventions.
