# 1. Why we need a common task engine

The ERP contains many workflows that require tasks.

Examples:

- PMO tasks
- Project Coordinator tasks
- UI tasks
- UX tasks
- Development tasks
- QA tasks
- Bug-fixing tasks
- Internal follow-up tasks
- Customer-response tasks
- Project actions
- Resource assignments
- Sprint work

Do NOT create separate task tables such as:

```text
ui_tasks
ux_tasks
dev_tasks
qa_tasks
pmo_tasks
```

That would create unnecessary duplication.

Instead, create one reusable task engine.

Conceptually:

```text
Project
   │
   └── Tasks
         ├── UI
         ├── UX
         ├── Development
         ├── QA
         ├── PMO
         └── Other
```

The department/workstream is represented through task metadata.

# 3. Important distinction: Actions vs Tasks

Existing:

```text
project_actions
```

is intended for high-level project actions such as:

```text
PAYMENT_FOLLOW_UP
CLIENT_RESPONSE_REQUIRED
CONTENT_REQUIRED
APPROVAL_REQUIRED
MEETING_REQUIRED
INTERNAL_ACTION
```

The new task engine is for actual work execution.

Example:

### Project Action

```text
Client needs revised content.
```

### Tasks

```text
Content collection task
↓
UI update task
↓
Development task
↓
QA verification task
```

Do not automatically delete or replace `project_actions`.

If there is a clear opportunity to reuse task functionality later, document it.


# 21. Dependency constraints

A task should not depend on itself.

Conceptually:

```text id="r8q3m1"
task_id != depends_on_task_id
```

If this cannot be cleanly enforced through the current Prisma/PostgreSQL setup, enforce it in the NestJS service and document it.

Prevent duplicate dependency records using an appropriate unique constraint:

```text id="m5v7x2"
task_id + depends_on_task_id + dependency_type
```

if compatible with the business rules.

# 33. Soft deletion

If `projects` and other operational entities use:


Do not physically delete task history.

If a task is no longer valid, prefer:

```text id="x7q3m1"

```

and preserve the record.

# 36. Avoid circular cascade problems

Be careful with:

```text

```

and:

```text

```

Do not configure destructive cascading behavior that could accidentally delete large task trees.

Use safe delete/update behavior consistent with the existing schema.

Document the chosen behavior.
